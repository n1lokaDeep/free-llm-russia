СервисПричина

Cloudflare WARP эндпоинты :894 заблокированы провайдером
Почему WARP не помогает. Совет «поставь WARP» в РФ не работает: 188.114.97.170:894 заблокирован, api.cloudflareclient.com в таймауте. Регистрация не проходит, и клиенты падают с netip.ParsePrefix("/24"). Ирония: WARP выдаёт адрес Cloudflare, а блокирует вас тоже Cloudflare.

Как отличить блокировку от проблемы с ключом

403 + Access denied by security policy  →  блок по IP, ключ ни при чём
401 + Authentication Fails              →  ключ неверный или не от того сервиса
404 + Not found for account             →  модель недоступна аккаунту
429                                     →  лимит исчерпан

Проверка одной командой:

Invoke-RestMethod https://api.ipify.org

Смена ключа при 403 не помогает. Проверено: два разных ключа дали одинаковый 403 с одного IP.

Готовые скрипты

ФайлНазначение
check-configs.py отобрать живые конфиги из публичного списка
verify-live.py проверить реальным запросом, какие работают
start-proxy.ps1 поднять локальный прокси на 127.0.0.1:18888
proxy.ps1 управление: start / stop / restart / status

Замер: из 5681 конфига живыми оказались 2. TCP-порт может быть открыт, а рукопожатие Reality — не проходить. Поэтому verify-live.py сравнивает выходной IP с вашим собственным: если совпали — трафик шёл напрямую, а не через прокси.

Ошибка, которую совершают все

# ТАК НЕ НАДО — сломает другие программы
[Environment]::SetEnvironmentVariable('HTTPS_PROXY','http://127.0.0.1:18888','User')

Игры и лаунчеры начнут ходить через прокси и падать с ConnectFail. Задавайте прокси только внутри процесса:

$env:HTTPS_PROXY = 'http://127.0.0.1:18888'
& myapp.exe
